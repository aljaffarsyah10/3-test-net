# TEST-NET — Product Requirements Document (PRD) & Sequential Development Playbook



MVP Specification

10 Development Phases



Dokumen ini menjadi pedoman utama pengembangan test-net, website pengujian kecepatan dan kualitas koneksi internet seperti Ookla Speedtest.

Pengembangan dilakukan secara bertahap menggunakan AI Coding Assistant / Vibe Coding di VS Code. Setiap phase harus diselesaikan, diuji, direview, dan mendapatkan persetujuan sebelum melanjutkan ke phase berikutnya.

### Keputusan arsitektur utama

Next.js + Dedicated Speed Test Server

User Browser

UI dan pengukuran melalui browser

Next.js Application

UI, routing, konfigurasi, metadata

LibreSpeed Dedicated Server

Ping, download, upload, throughput measurement

Alasan pemisahan:

- Next.js tidak dirancang menjadi data plane untuk transfer data speed test berukuran besar.
- Dedicated server dapat mengelola bandwidth, concurrency, dan payload secara lebih terkontrol.
- Infrastruktur speed test dapat dikembangkan menjadi multi-server.
- UI dan engine dapat dikembangkan secara terpisah.

LibreSpeed menjadi pilihan utama, tetapi versi, lisensi, API, dan metode integrasinya wajib divalidasi pada Phase 2 sebelum implementasi.

# PART A — PRODUCT REQUIREMENTS DOCUMENT

## 1. Product Information

Nama produk: test-net

Deskripsi:

Website publik untuk mengukur kualitas koneksi internet secara langsung melalui browser. Pengguna dapat mengetahui download speed, upload speed, ping, dan jitter tanpa membuat akun.

Target pengguna:

- Pengguna internet rumahan.
- Pekerja remote.
- Pelajar dan mahasiswa.
- Pengguna yang ingin memeriksa kualitas jaringan.
- Pengguna teknis yang membutuhkan informasi latency dan jitter.

Project constraints:

- Solo developer.
- Tidak menggunakan microservices yang tidak diperlukan.
- Tidak menggunakan database pada MVP.
- Tidak ada authentication.
- Tidak ada payment atau subscription.
- Tidak menggunakan Rust atau Tauri.
- Tidak menggunakan Next.js API untuk transfer payload speed test.
- Tidak mengimplementasikan fitur P2 sebelum MVP selesai.

## 2. Product Overview

### Problem

Pengguna internet sering mengalami perbedaan antara kecepatan internet yang dijanjikan provider dengan kecepatan aktual yang mereka rasakan.

Mereka membutuhkan alat sederhana untuk mengetahui kondisi koneksi saat ini.

### Solution

test-net menyediakan pengujian koneksi internet berbasis transfer data aktual antara browser pengguna dan dedicated test server.

### Cara kerja

1. Pengguna membuka website.
2. Website memuat konfigurasi test server.
3. Pengguna menekan tombol Start.
4. Sistem melakukan pengukuran latency.
5. Sistem mengukur jitter.
6. Sistem melakukan download test.
7. Sistem melakukan upload test.
8. Sistem menampilkan hasil pengukuran.
9. Pengguna dapat mengulangi tes.

### Nilai utama

- Tidak membutuhkan akun.
- Mudah digunakan.
- Pengukuran aktual.
- Tampilan sederhana.
- Mendukung desktop dan mobile.
- Dapat dikembangkan menjadi layanan multi-server.

### Definisi pengukuran

Download

Mengukur jumlah byte yang diterima browser dibagi durasi pengukuran.

Upload

Mengukur jumlah byte yang dikirim browser dibagi durasi pengukuran, mengikuti metodologi engine.

Ping

Menggunakan HTTP round-trip latency ke server, bukan ICMP ping. Ini harus dijelaskan dalam dokumentasi metodologi.

Jitter

Menggunakan rata-rata selisih absolut antara sampel latency berurutan, kecuali engine terpilih memiliki definisi lain yang diputuskan dan didokumentasikan.

Satuan:

- Download: Mbps.
- Upload: Mbps.
- Ping: ms.
- Jitter: ms.

```
  id: string;
  name: string;
  endpoint: string;
}
```

### Storage

| Data           | Storage              |
| -------------- | -------------------- |
| Server config  | Environment variable |
| Current result | React state          |
| History        | Tidak ada pada MVP   |
| User account   | Tidak ada            |
| Database       | Tidak ada            |

## 14. Security & Privacy

- HTTPS wajib.
- CORS hanya untuk origin yang diizinkan.
- Rate limiting.
- Batas ukuran payload.
- Batas durasi tes.
- Batas concurrency.
- Tidak menerima arbitrary URL upload.
- Tidak menyimpan payload.
- Tidak menyimpan hasil ke server.
- Tidak memasukkan secret ke environment variable publik.
- Privacy notice menjelaskan bahwa dedicated test server menerima alamat IP sumber sebagai bagian normal koneksi.

Contoh `.env.example`:

```
NEXT_PUBLIC_SPEEDTEST_SERVER_URL=https://speed-server.example.com
NEXT_PUBLIC_SPEEDTEST_SERVER_NAME=Primary Test Server
```

## 15. Success Criteria

- Download test berjalan.
- Upload test berjalan.
- Ping tersedia.
- Jitter tersedia.
- Hasil berasal dari pengukuran nyata.
- Cancellation bekerja sesuai kemampuan engine.
- Retry bekerja.
- Estimasi penggunaan data ditampilkan.
- UI responsive.
- Dedicated test server berjalan.
- HTTPS dan CORS benar.
- Tidak menggunakan mock di production.
- Testing lulus.
- Deployment production berhasil.

## 16. Risks & Technical Constraints

| Risiko                    | Mitigasi                         |
| ------------------------- | -------------------------------- |
| Bandwidth VPS terbatas    | Benchmark kapasitas server       |
| Server jauh dari pengguna | Tampilkan lokasi server          |
| Traffic berlebihan        | Rate limiting                    |
| Cache memengaruhi hasil   | Cache-busting                    |
| CORS gagal                | Konfigurasi allowlist            |
| Browser throttling        | Penanganan tab tidak aktif       |
| Engine berubah            | Pin versi engine                 |
| Biaya bandwidth tinggi    | Batas durasi dan payload         |
| Server overload           | Concurrency limit dan monitoring |

## Rekomendasi urutan pengerjaan

Untuk project ini, ada satu hal penting: Phase 2 harus benar-benar memvalidasi LibreSpeed sebelum kamu menghabiskan waktu membangun integrasi frontend.

Jangan menganggap dedicated server otomatis memiliki bandwidth cukup hanya karena VPS berhasil menjalankan aplikasi. Kapasitas bandwidth, lokasi server, concurrency, dan biaya transfer data merupakan faktor utama dalam produk speed test publik.

Target akhir test-net: website speed test publik dengan pengukuran download, upload, ping, dan jitter secara aktual, menggunakan Next.js sebagai frontend dan dedicated LibreSpeed server sebagai measurement engine.
